## Stock falls when an order is placed

Not when it is paid, and not when it is shipped — when the order is placed. That is what stops two
shoppers buying the last one in the same minute.

If an order fails part-way through — a payment that does not complete, a gateway that times out —
the stock it reserved is given back. You do not have to correct it by hand.

## At zero

A product with no stock is shown as unavailable rather than removed. The page keeps working, which
matters: the link may be in somebody's message, on a social post, or in a search result, and a
dead link is worse than an honest "out of stock".

## Checking before you promise

Stock in the dashboard is the same number the shop uses. If it says two, there are two. The admin
app shows the same figure, so you can check it from the counter without going to a computer.
