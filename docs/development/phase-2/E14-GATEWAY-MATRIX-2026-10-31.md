matrix row for each of the nineteen gateway returns the old F220 census named, plus a

## Read this before the table

**The census these nineteen came from was wrong, and the run said so independently.** Its own
verification reported the four headline numbers (31 / 8 / 19 / 4) as all incorrect, with two
derivation faults: `Order::create\s*\(` has no left anchor so it matched inside
`PlanOrder::create(`, and the glob was non-recursive so `app/Http/Controllers/Api/` was
invisible. **None of the nineteen below writes a customer `App\Models\Order`** — every one
writes `App\Models\PlanOrder`, a SaaS plan sale. `GatewayReplayGuardCensusTest` was rewritten
on that finding (commit `67de44ed`); the measured truth is 15 customer-order write sites in 11
files, and the corrected row is F220 in the ledger.

**So these rows are evidence about PLAN-PURCHASE returns, not about order writers.** They
remain the most complete account of those nineteen surfaces that exists, and four of them
(Benefit, Cashfree, Mollie, Paytm) were acted on in commit `139bcc22` — see F228, F229, F232.
Everything here is a *reading of source by an agent*, confirmed for the four that were acted
on and NOT independently re-verified for the other fifteen. Treat an unverified row as a lead,
not as a measurement.
